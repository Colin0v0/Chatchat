# Chatchat 部署与模型接入说明

更新时间：2026-04-27

本文档描述当前推荐部署形态：纯 CPU 服务器 + 云端模型 API + 本地 Docker 数据库。它面向三五个人的小团队使用场景，重点说明哪些东西跑在本机，哪些东西走外部 API，以及环境变量该怎么配。

## 1. 当前结论

当前 Chatchat 不再走本地模型推理：

- 不使用 Ollama
- 不加载本地 OCR / 视觉模型
- 不加载本地 ASR
- 不加载本地 embedding 模型
- 不加载本地 reranker 模型
- 不需要 GPU

本机仍然会运行：

- FastAPI 后端
- React 前端静态服务
- PostgreSQL + pgvector
- Redis
- 文件解析器，例如 PDF / DOCX / XLSX / CSV / Markdown 文本抽取
- 媒体附件与知识库原文存储

这些属于应用基础设施，不是本地模型推理。

## 2. 模型与服务分工

| 能力 | 当前推荐 | 配置来源 | 说明 |
| --- | --- | --- | --- |
| 普通聊天 | DeepSeek 官方 API | `DEEPSEEK_BASE_URL` / `DEEPSEEK_API_KEY` | `model_catalog.json` 里 DeepSeek 使用 OpenAI-compatible 协议，但 key 是 DeepSeek 的 |
| embedding | 百炼/DashScope `text-embedding-v4` | `DASHSCOPE_API_KEY`，可选 `KNOWLEDGE_EMBEDDING_*` | 默认复用 DashScope key |
| rerank | 百炼/DashScope `gte-rerank-v2` | `DASHSCOPE_API_KEY`，可选 `KNOWLEDGE_RERANK_*` | 旧 Codex/OpenAI/Ollama rerank 路径已删除 |
| 网页搜索 | 百炼/DashScope 原生联网搜索 | `DASHSCOPE_API_KEY`，可选 `WEB_SEARCH_*` | 使用 `output.search_info.search_results` 做来源展示、rerank 和上下文注入 |
| 语音转写 | 百炼/DashScope `qwen3-asr-flash` | `DASHSCOPE_API_KEY`，可选 `AUDIO_TRANSCRIPTION_*` | 后端只做上传校验和 API 调用 |
| 云端音色 | 百炼/DashScope `cosyvoice-v3-flash` | `DASHSCOPE_API_KEY`，可选 `AUDIO_TTS_*` | 设置页可和浏览器本机音色切换 |
| 图片上传给聊天模型 | DeepSeek 默认关闭 | `model_catalog.json` | DeepSeek v4 Flash / Pro 的 `capabilities.input.image=false` |
| 图片生成 | 可选 OpenAI-compatible 图片接口 | `OPENAI_IMAGE_*` | 这是外部 API，不是本地模型 |

`KNOWLEDGE_EMBEDDING_API_KEY`、`KNOWLEDGE_RERANK_API_KEY`、`WEB_SEARCH_API_KEY`、`AUDIO_TRANSCRIPTION_API_KEY` 这类细分 key 是为了以后拆分供应商或账号。当前全部走百炼时可以留空，系统会回退到 `DASHSCOPE_API_KEY`。

## 3. 请求链路

```text
浏览器
  -> frontend
  -> backend
      -> DeepSeek API：聊天
      -> DashScope API：embedding / rerank / ASR / TTS
      -> PostgreSQL + pgvector：用户、会话、消息、知识库向量
      -> Redis：缓存/会话辅助/运行状态
      -> storage/：附件、媒体文件、知识库原文
```

RAG 不启用时，请求基本只会经过聊天模型和数据库。RAG 启用并且命中知识库时，才会额外调用 embedding / rerank。

## 4. 推荐服务器规格

三五个人一起用、RAG 很少使用的情况下：

| 档位 | 规格 | 适合场景 |
| --- | --- | --- |
| 最小可跑 | 2 vCPU / 4GB / 40GB SSD | 聊天为主，低并发，少量文件上传 |
| 推荐 | 2 vCPU / 8GB / 60GB SSD | 三五个人日常使用，数据库和文件解析更稳 |
| 更舒服 | 4 vCPU / 8GB+ / 80GB SSD | 同时上传文件、批量建知识库索引、多人并发更从容 |

网络方面，日常聊天 1-5 Mbps 带宽通常够用；如果多人上传文件或使用语音，优先选更稳定的上行和更好的外网访问质量。因为模型都在外部 API，延迟主要取决于服务器访问 DeepSeek 和百炼的网络质量。

## 5. 最小环境变量

生产 Docker 默认会加载：

- `backend/.env`
- `backend/.env.deploy.wsl`

核心变量建议保持下面这组：

```env
DATABASE_URL=postgresql+psycopg://chatchat:chatchat@postgres:5432/chatchat
REDIS_URL=redis://redis:6379/0

DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_API_KEY=

DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_API_KEY=

DEFAULT_PROVIDER=openai
DEFAULT_MODEL=openai:deepseek-v4-flash
MODEL_CATALOG_PATH=./model_catalog.json
MODEL_CATALOG_STRICT=true

KNOWLEDGE_EMBEDDING_PROVIDER=dashscope
KNOWLEDGE_EMBEDDING_MODEL=text-embedding-v4
KNOWLEDGE_EMBEDDING_DIMENSIONS=1024

KNOWLEDGE_RERANK_PROVIDER=dashscope
KNOWLEDGE_RERANK_MODEL=gte-rerank-v2

AUDIO_TRANSCRIPTION_ENABLED=true
AUDIO_TRANSCRIPTION_MODEL=qwen3-asr-flash

AUDIO_TTS_ENABLED=true
AUDIO_TTS_MODEL=cosyvoice-v3-flash
AUDIO_TTS_VOICE=longanyang
```

如果不接 Codex、Gemini、Claude、Trio，对应 key 可以留空；只要模型目录里仍有启用模型依赖这些 provider，调用它们时才需要配置 key。

## 6. 可选环境变量

### 6.1 细分 API key

这些变量不是必填：

```env
KNOWLEDGE_EMBEDDING_BASE_URL=
KNOWLEDGE_EMBEDDING_API_KEY=
KNOWLEDGE_RERANK_BASE_URL=
KNOWLEDGE_RERANK_API_KEY=
AUDIO_TRANSCRIPTION_BASE_URL=
AUDIO_TRANSCRIPTION_API_KEY=
AUDIO_TTS_BASE_URL=
AUDIO_TTS_API_KEY=
```

留空时的默认行为：

- embedding 使用 `DASHSCOPE_BASE_URL` + `DASHSCOPE_API_KEY`
- rerank 使用百炼 rerank 默认 endpoint + `DASHSCOPE_API_KEY`
- ASR 使用 `DASHSCOPE_BASE_URL` + `DASHSCOPE_API_KEY`
- TTS 使用百炼语音合成默认 endpoint + `DASHSCOPE_API_KEY`

只有当你要把 embedding、rerank、ASR、TTS 拆到不同网关、不同账号或不同代理时，才需要单独填写。

### 6.2 网页搜索

```env
WEB_SEARCH_PROVIDER=dashscope
WEB_SEARCH_BASE_URL=https://dashscope.aliyuncs.com/api/v1/services/aigc/text-generation/generation
WEB_SEARCH_API_KEY=
WEB_SEARCH_MODEL=qwen-plus
WEB_SEARCH_STRATEGY=turbo
WEB_SEARCH_FORCED=true
WEB_SEARCH_ENABLE_SOURCE=true
WEB_SEARCH_ENABLE_CITATION=true
WEB_SEARCH_CITATION_FORMAT=[ref_<number>]
WEB_SEARCH_MAX_RESULTS=5
WEB_SEARCH_TOP_K=4
WEB_SEARCH_MIN_SCORE=0.2
WEB_SEARCH_CONTENT_MAX_CHARS=1600
WEB_SEARCH_TRANSLATION_MODEL=codex:gpt-5.2
```

网页搜索使用 DashScope 原生 Generation API 的联网搜索能力。`WEB_SEARCH_API_KEY` 留空时复用 `DASHSCOPE_API_KEY`；后端从 `output.search_info.search_results` 映射出来源，再继续走现有 dedupe、filter、rerank 和上下文注入。

### 6.3 图片生成

```env
OPENAI_IMAGE_BASE_URL=
OPENAI_IMAGE_API_KEY=
OPENAI_IMAGE_MODEL=gpt-image-2
OPENAI_IMAGE_SIZE=1024x1024
OPENAI_IMAGE_QUALITY=auto
OPENAI_IMAGE_OUTPUT_FORMAT=png
```

这组只影响图片生成 API，不影响 DeepSeek 聊天，也不代表本机要加载图片模型。不使用图片生成时可以留空。

### 6.4 并发控制

```env
MODEL_MAX_CONCURRENCY_PER_MODEL=2
OPENAI_HTTP_MAX_CONCURRENCY=8
WEB_SEARCH_HTTP_MAX_CONCURRENCY=4
ATTACHMENT_PROCESSING_MAX_CONCURRENCY=2
MEMORY_REFRESH_MAX_CONCURRENCY=1
```

小服务器建议先保守一些。三五个人使用时，`MODEL_MAX_CONCURRENCY_PER_MODEL=2` 通常更稳，避免文件解析、数据库检索和外部 API 调用同时堆高。

## 7. Docker 启动

前后端镜像在本地电脑或高配构建机上构建，再推送到阿里云 ACR；服务器只执行 pull 和启动。

默认会启动：

- `postgres`
- `redis`
- `backend`
- `frontend`

### 7.1 本地构建并推送镜像

在项目根目录准备 `.env`：

```env
POSTGRES_IMAGE=registry.cn-hangzhou.aliyuncs.com/你的命名空间/chatchat-pgvector:pg16
REDIS_IMAGE=registry.cn-hangzhou.aliyuncs.com/你的命名空间/chatchat-redis:7-alpine
BACKEND_IMAGE=registry.cn-hangzhou.aliyuncs.com/你的命名空间/chatchat-backend:latest
FRONTEND_IMAGE=registry.cn-hangzhou.aliyuncs.com/你的命名空间/chatchat-frontend:latest
POSTGRES_DB=chatchat
POSTGRES_USER=chatchat
POSTGRES_PASSWORD=请改成强密码
POSTGRES_PORT=5432
REDIS_PORT=6379
BACKEND_DATABASE_URL=postgresql+psycopg://chatchat:请改成强密码@postgres:5432/chatchat
BACKEND_REDIS_URL=redis://redis:6379/0
AUDIO_TRANSCRIPTION_MODEL=qwen3-asr-flash
BACKEND_PORT=8000
FRONTEND_PORT=3300
BACKEND_STORAGE_HOST_PATH=./storage
DOCKER_REGISTRY=docker.io
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
```

构建和推送：

```bash
docker login registry.cn-hangzhou.aliyuncs.com
docker pull pgvector/pgvector:pg16
docker pull redis:7-alpine
docker tag pgvector/pgvector:pg16 "$POSTGRES_IMAGE"
docker tag redis:7-alpine "$REDIS_IMAGE"
docker compose -f docker-compose.yml -f docker-compose.build.yml build backend frontend
docker push "$POSTGRES_IMAGE"
docker push "$REDIS_IMAGE"
docker push "$BACKEND_IMAGE"
docker push "$FRONTEND_IMAGE"
```


启动：

```bash
docker login registry.cn-hangzhou.aliyuncs.com
docker compose pull
docker compose up -d
```

常用检查：

```bash
docker compose ps
docker compose logs -f backend
curl http://127.0.0.1:8000/api/health
```

前端默认暴露在：

```text
http://服务器IP:3300
```

后端默认暴露在：

```text
http://服务器IP:8000
```

公网部署时建议只暴露前端入口，后端由反向代理转发，不要直接把数据库和 Redis 暴露到公网。

## 8. 知识库与 RAG

当前知识库链路：

```text
上传 Markdown / 文件夹
  -> 存入 storage/knowledge
  -> 点击更新知识库
  -> 调用 DashScope embedding
  -> 写入 PostgreSQL pgvector
  -> 检索时按向量/关键词召回
  -> 可选 DashScope rerank
```

如果 RAG 基本不用，可以保留默认配置，不需要额外资源。真正占资源的是批量上传和重建索引时的文件解析、embedding API 调用和数据库写入。

知识库现在支持逻辑文件夹分组：

- 单文件/多文件上传时可以指定分组
- 上传文件夹时会保留浏览器提供的相对路径
- 文档可以批量移动到其他分组
- 聊天开启知识库模式后，可以限定只检索某个分组

分组是数据库 metadata，不依赖服务器物理目录；服务器上的原文仍按用户和文档 id 管理，便于删除、迁移和权限隔离。

切换 embedding 模型或维度后，旧向量需要重新索引，否则检索结果会不一致。

## 9. 语音与音色

语音输入：

- 浏览器录音上传到后端
- 后端做时长、大小、音量阈值校验
- 后端调用 DashScope ASR
- 返回文本给对话框

语音播放：

- 浏览器本机音色：走浏览器 SpeechSynthesis，不消耗后端 TTS API
- 阿里云音色：走 DashScope TTS，后端返回音频

设置页可以选择使用本机音色还是阿里云音色。阿里云音色数量取决于当前 DashScope TTS 模型和账号权限。

## 10. 本地模型旧路径状态

以下旧路径已经不再保留：

- Ollama provider / transport / codec / runtime
- `openai_local` provider
- 本地 OCR / image vision
- 本地 SenseVoice / FunASR ASR
- 本地 embedding
- 本地 reranker
- 本地模型 idle cache / eager load

如果后续要接新模型，优先走云端 API provider 和 `backend/model_catalog.json`，不要重新引入本机常驻模型。
