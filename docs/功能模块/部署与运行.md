# 部署与运行

更新时间：2026-04-27

## 1. 推荐部署形态

当前推荐：

- 后端 FastAPI 容器或宿主机进程
- 前端 Vite 构建产物
- PostgreSQL + pgvector
- Redis
- 本地或对象存储保存媒体文件
- DeepSeek 和 DashScope 通过外部 API 调用

不需要 GPU。

## 2. 本地开发

启动开发基础设施：

```powershell
docker-compose -f docker-compose.dev-infra.yml up -d
```

启动后端：

```powershell
cd backend
.\scripts\run_dev_backend.ps1
```

启动前端：

```powershell
cd frontend
pnpm install
pnpm run dev
```

## 3. Docker 部署

前后端镜像先在本地电脑或高配构建机上构建并推送到阿里云 ACR：

```bash
docker login registry.cn-hangzhou.aliyuncs.com
docker pull pgvector/pgvector:pg16
docker pull redis:7-alpine
docker tag pgvector/pgvector:pg16 "$POSTGRES_IMAGE"
docker tag redis:7-alpine "$REDIS_IMAGE"
docker compose -f docker-compose.yml -f docker-compose.build.yml build backend frontend
docker push "$POSTGRES_IMAGE"
docker push "$REDIS_IMAGE"
docker push "$BACKEND_IMAGE"
docker push "$FRONTEND_IMAGE"
```

服务器只拉取镜像并启动：

```bash
docker login registry.cn-hangzhou.aliyuncs.com
docker compose pull
docker compose up -d
```

默认包含：

- backend
- frontend/nginx
- postgres/pgvector
- redis

## 4. 小团队服务器建议

三五个人同时使用，纯 CPU/API 方案可以从：

- 2 vCPU
- 4 GB RAM
- 40 GB SSD

起步。

更稳建议：

- 4 vCPU
- 8 GB RAM
- 80 GB SSD

主要资源压力来自：

- PostgreSQL + pgvector
- 文件解析
- 并发流式响应
- Redis
- 外部 API 等待导致的连接占用

## 5. 生产注意事项

建议：

- `DATABASE_URL` 使用持久化 PostgreSQL。
- Redis 使用持久服务或 Docker volume。
- `MEDIA_ROOT` 和 `KNOWLEDGE_STORAGE_ROOT` 持久化。
- API Key 通过环境变量注入，不写入镜像。
- 反向代理设置合理的流式超时。
- 小服务器限制并发参数。

关键并发参数：

```env
MODEL_MAX_CONCURRENCY_PER_MODEL=2
WEB_SEARCH_HTTP_MAX_CONCURRENCY=4
ATTACHMENT_PROCESSING_MAX_CONCURRENCY=2
MEMORY_REFRESH_MAX_CONCURRENCY=1
```
